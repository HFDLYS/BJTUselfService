## 必守的坑

- 缓存是 AES 加密的，密钥在 Keychain/DPAPI。CLI 只能经 App 自己的启动器运行（`Contents/MacOS/BJTUselfServiceKMP agent …`，Windows 是 exe）；jpackage 运行时里没有 java。
- 绝不用 `createDesktopCacheStore` / `openCacheStoreWithRecovery` 打开缓存，它们会新建密钥、删库。用 `openExistingCacheStore(file, key, readOnly)`。
- 绝不调用 `AccountSecurityCoordinator.restore()`：未记住密码时它会清除凭据。
- App 运行时持有 `app-running.lock`；要登录学校系统的命令先 `AgentAppLock.tryAcquire`，拿不到就退出码 6。
- 先校验参数，再读缓存（否则参数写错也会触发钥匙串授权）。
- 测试只用临时目录 / 临时 HOME；不要碰用户真实的 `~/.agents`、Keychain、缓存。

## PR D：CITEL 题面与测试用例导出 Markdown（分支 `feat/ai-agent-citel`）

目标：用户要做某道题或要拉全文时，拿到完整题面和测试用例，保存成 `.md`（以及 `tests/1.in`、`tests/1.out`），agent 也能读。**平时同步不下载用例原文。**

页面结构（详见 spike 第 4 节）：
- 题面：`mod/programming/view.php?id=<模块>` 里的 `#description > .no-overflow`，原始 HTML，公式是 `$...$` TeX，原样保留即可。标题在 `h1.name`；`div.grade` 是分值和输入输出方式。
- 公开用例：`#pub-testcase-table tbody tr:not(.emptyrow)`，每行 5 格（名称、输入、输出、时间限制、内存限制）。输入、输出格里的 `a.showasplaintext` 指向 `testcase/download_io.php?a=..&test=..&type=in|out&download=0`。**页内预览会截断**，原文必须走 download_io。
- 提交过的题：`result.php?a=<活动号>`，表 `#test-result-detail-table > tbody > tr:not(.emptyrow)`，13 列。第 4、5、6 格是输入、期望输出、我的输出的 download_io 链接（我的输出带 `submit=`）。这里能拿到**全部**用例，包括非公开用例；“Secure test”这个标签并不表示隐藏。
- 只用页面上出现的链接，不猜 test id；所有 URL 都过 `isCitelUrl`。

要做的：
1. **解析**：`CitelParser.kt` 新增 `parseCitelProblem(html)`，得到 `CitelProblem(title, gradeLine, statementHtml, publicCases)`；扩展结果页解析，读出第 4–6 格的链接。解析放在 `parseOffMain` 里。补一个 HTML 转 Markdown 的小工具（h1–h6、p、div/br、pre→代码块、ul/ol、b/i、a、img、简单 table）。
2. **网络**：`CitelRemote` 新增 `problem(credentials, task, withResults)`，复用现有的 `page()`（已处理掉线后重新登录）和 `request()`。活动号 `a` 从 view 页面的链接里取。I/O 用 GET 拿 `text/plain` 原文，行尾是 CRLF，需要统一处理。
3. **缓存**：写到 `cache_metadata` 的 `citel.problem.<模块id>`（自动加密），不改 schema。
4. **Markdown**：新建 `feature/citel/CitelProblemMarkdown.kt`（纯函数），依次写元数据、题面、样例、各用例（输入、期望输出；提交过的题再加我的输出、是否通过、耗时）。导出文件夹时生成 `problem.md` 和 `tests/N.in`、`tests/N.out`，用 `CoursewareDirectoryGateway`。
5. **UI**：`CitelScreen.kt` 的 `CitelDetailWorkspace` 加“获取题目全文 / 复制 Markdown / 保存 / 导出文件夹”，用户点了才联网。`AssignmentMarkdown.kt` 里 CITEL 部分有缓存题面时带上题面。
6. **CLI**：`agent citel show <id> [--fetch] [--json]`、`agent citel export <id> --out <目录> [--fetch]`。不加 `--fetch` 只读缓存；加了才联网。CITEL 凭据用 `securityStore.citelVault(学号)`，账号名在缓存的 `citel.username`。Skill 里补上用法，并写明“需要题面时问用户再 `--fetch`”。
7. **测试**：用虚构 fixture 覆盖题面两种写法（h4+pre，以及 div/br）、emptyrow 过滤、download_io 链接提取、结果页嵌套表格、非公开用例、登录过期、Markdown 渲染和文件夹结构。

## PR E：Mac 卸载清理（分支建议 `feat/ai-agent-uninstall`，基于 D）

目标：用户删掉 App 前，能把本机所有痕迹清干净。

1. **CLI** `agent uninstall-app [--yes]`（名字可以再议，不要和 Skill 的 `uninstall` 混淆），默认 dry-run，只列出将删的项目；加 `--yes` 才执行。清理范围：
   - `~/Library/Application Support/BJTUselfServiceKMP`（缓存库、`-wal`/`-shm`、标记文件、锁文件）
   - 本 App 自己的 `java.util.prefs` 节点（`/team/bjtuss/bjtuselfservice/kmp/...`），用 `Preferences.node(..).removeNode()`，**不要删共享的** `~/Library/Preferences/com.apple.java.util.prefs.plist`
   - Keychain：`MACOS_SECRET_BAG_SERVICE` 和所有 `LEGACY_*` 服务（见 `MacOsSecretBag.kt`），复用 `MacOsKeychainItem.clear`
   - Skill 和启动脚本：调用 `DesktopAgentIntegration.uninstall()`
   - 最后把 `.app` 移到废纸篓（Finder，可以恢复），不做永久删除
2. **复用**：设置页现有的“清除全部本地数据”（`SettingsScreenModel.clearAllLocalData` 和 `AuthenticatedSessionFactory` 里的 `wipeAllLocalData`）抽成同一个清理器（例如 desktopMain 的 `MacUninstallCleaner`），设置页和 CLI 共用。设置页再加“卸载前清理（含移除 AI 助手）”。
3. **测试**：只在临时 HOME 和测试用 Keychain service 里跑真删除；真机上只跑 dry-run。
4. Windows 暂不做，用户只要求了 Mac。
