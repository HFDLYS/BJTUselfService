# AI Agent Spike 记录（2026-10-14，`feat/ai-agent`）

## 1. macOS：经 App 启动器跑无界面 CLI —— 可行

探针：`desktopApp/.../Main.kt` 开头的 `agent` 分派（先设 `java.awt.headless=true`）+ `shared/src/desktopMain/.../agent/AgentSpikeProbe.kt`（只用独立 Keychain 服务 `team.bjtuss.bjtuselfservice.kmp.agent-spike`，不碰 App 的真实条目）。用 `./gradlew :desktopApp:createDistributable` 生成源码版 `.app`，直接执行 `Contents/MacOS/BJTUselfServiceKMP agent spike …`。

| 检查 | 结果 |
|---|---|
| stdout 走管道 | `… agent spike info \| python3 -c 'json.load(sys.stdin)'` 解析成功；`headless=true` |
| 退出码 | 成功为 0；未知子命令为 64，usage 打到 stderr |
| 启动耗时 | 第一次 1.53 s（冷启动和 Gatekeeper 检查），之后 0.09–0.11 s |
| Dock 图标 | 运行期间 `lsappinfo list` 里查不到这个 pid，说明进程没有注册为 GUI 应用 |
| Keychain（同一二进制） | 写入后连续读两次都没弹授权，摘要一致；`keychain-clear` 后已确认删掉 |
| 能否用内置 `java` 直接跑 | **不行**：jpackage 裁剪过的运行时里没有 `bin/java`，所以 macOS 上**只能**经启动器运行，与计划一致 |

`jpackage.app-path` 系统属性能拿到启动器的绝对路径，`agent install` 可以用它写出启动脚本。

## 2. Windows：经 App 自己的 exe 运行 —— 可行（CI windows-latest 实测）

- jpackage 运行时里**没有** `java.exe` 或 `javaw.exe`（`Test-Path` 都为 False），所以 Windows 上也只能走 App 的 exe。
- 管道调用 `exe agent spike info | Out-String`：能拿到 stdout，exit 0，约 0.3–0.44 s。
- 用 agent 的方式启动（`ProcessStartInfo` 重定向 stdout/stderr，`UseShellExecute=false`）：stdout 完整拿到，exit 0。
- DPAPI 往返（独立节点，非真实凭据）：加密、解密、清除都成功。未知子命令的退出码是 64。
- 这个探针 workflow 已改成正式的 `agent-cli-windows.yml` 冒烟测试，跑真实命令：`help`、无缓存时 `status --json` 退出码 2、参数错误退出码 64。

## 3. Skill 目录

- 本机 `~/.claude/skills` 是指向 `~/.agents/skills` 的**软链接**。所以安装时必须先判断：如果它已经指向 `~/.agents/skills`，就**不要**再建链接（否则会链回自己）；只有它是普通目录时才在里面建一个指向 Skill 的链接。
- Codex 官方文档写明用户级 Skill 目录是 `$HOME/.agents/skills`（旧的 `$CODEX_HOME/skills` 仍兼容），新装的 Skill 要新开会话才生效。本机没装 codex CLI，所以没有实测。
- 现有 `~/.agents/.skill-lock.json` 是 vercel `skills` CLI 的记录文件，我们的安装器不往里写，免得被那个工具误当作它装的而更新或删除。

## 5. 物理在线“已选课” —— 用户确认是第二种情况

用户回答：物理在线里“物理实验”这门课的作业**列着本学期全部实验**，学生只需要交自己约上的那几个。

规则：物理在线里物理实验课的活动，按实验名和物理实验选课系统的约课结果（`physicslab.results` 里的 `PhysicsLab.name`）匹配，只保留对上的；其他课（非物理实验）照常全部保留。

待做：实验名的匹配方式（活动标题和 `PhysicsLab.name` 是否完全一致、要不要去掉“实验报告”之类的前后缀）需要真实标题对照。源码版读不了真实缓存（Keychain ACL 绑定的是安装版），可以让用户在物理在线页面和约课结果里各报几个名字，或者在用户同意时，让源码版弹一次 Keychain 授权后只在内存里比对。还要处理约课缓存为空（没配置 wlsy 账号）的情况：不过滤，标 `enrollmentUnverified`。

**真实标题对照（2026-10-14，用户截图和 App 内“物理实验同步”页）**
- 物理在线“物理实验II_(2026秋)”的作业标题形如 `33 光栅光谱仪测光谱（难度系数1.1）`、`34 光纤特性和光信号传输`、`37，38 万用表设计（难度系数1.1）`，即“序号 + 实验名 +（难度系数）”。
- 约课结果（wlsy）：`光纤特性和光信号传输`、`利用超声光栅测定液体中声速`（物理实验），`声源定位的GPS模拟`（设计实验），`超声专题`（专题实验）。
- 规则：两边都归一化后再比较。归一化去掉开头的序号（`\d+` 以及 `，`/`,`/`、` 分隔的多个序号）和结尾的括号段（如“（难度系数…）”），再去掉空白、统一全半角。先比完全相等，不相等再看是否互相包含。前两项能直接对上。
- 设计实验和专题实验在作业列表里可能没有对应项，对不上的约课结果不强行匹配。CLI 只输出 `matchedBooking`，以及“约课缓存是否可用”的标志，剩下的交给 Skill 判断：没约上的实验不算待做，拿不准的列出来问用户。
- 物理在线上的其他课程（大学物理II、大学物理演示实验）不做这层过滤。
